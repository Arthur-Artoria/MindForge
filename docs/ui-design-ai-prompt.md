# MindForge 通用高保真 UI 设计提示词

> 用途：投喂给 Figma AI、界面生成器或其他支持自然语言的 AI 设计工具。
>
> 目标：生成覆盖 MindForge 全部 MVP 页面的高保真、响应式 Web UI，而不是生成前端代码。

## 使用方法

1. 将下面“通用母提示词”整体粘贴给设计工具，不需要附加其他材料。
2. 先完成无配色的布局和空间检查，再探索配色并渲染高保真界面。
3. 如果工具一次无法稳定生成全部页面，先执行母提示词中的全局设计系统，再按文末的分批顺序逐组生成。

## 通用母提示词

```text
你是一名擅长复杂生产力工具、知识管理产品和响应式 Web App 的资深产品设计师。请为产品 MindForge 设计一套完整、可实现、具有鲜明性格的高保真 UI。

你的任务不是套用常见 SaaS Dashboard 模板。请先理解产品工作流，再建立统一设计语言，并用它覆盖全部 MVP 页面。

一、产品背景

产品名称：MindForge

产品定位：
MindForge 是面向单个开发者的个人知识与项目中枢。它把技术笔记、链接收藏、个人项目、任务推进、附件和周期回顾组织在同一工作空间中，帮助用户减少上下文切换，把零散资料转化为可搜索、可关联、可持续复用的个人知识系统。

它不是团队协作平台，不是公开内容社区，不是企业管理后台，也不是 AI 聊天产品。MVP 服务一个有工程经验、长期学习并同时推进多个 side project 的个人开发者。

产品原则：
- 个人优先，不出现团队成员、审批、评论流、通知中心等企业协作噪音。
- 输入低摩擦，可以快速记录笔记、链接或任务，结构化字段允许稍后补充。
- 搜索优先，弱化传统文件夹树，不把深层目录作为核心导航。
- 项目驱动知识，笔记、链接、任务、附件和回顾之间要自然关联。
- 界面适合每天长时间使用，信息密度克制但不空洞。

二、核心视觉方向

为这套设计建立一个新的方向，可命名为 “Structured Workbench / 结构化工作台”。

设计关键词：
- 克制但不平庸
- 清晰、有重量的功能区域
- 编辑工具感，而不是管理后台感
- 安静、专注、适合长时间阅读和写作
- 现代、理性、略带实验性
- 高信息可读性
- 有鲜明识别度，但不依赖夸张主题装饰

不要预设 MindForge 必须使用某一种具体色相，也不要直接指定页面背景、侧栏、按钮或卡片应当是什么颜色。允许设计工具在中性色、单一主色系或低饱和复合色系之间探索，但最终只能选定一套清晰、可扩展的系统。

在进入高保真页面前，先提出 3 套彼此有明显区别的色彩方向，每套只输出色阶、角色映射和一个小型界面片段，不重新设计布局：
- 方向 A：以中性色为主，依靠明度和材质感建立层级。
- 方向 B：选择一种低饱和主色，以连续色阶组织界面。
- 方向 C：选择一种主色和一种受控辅助色，形成更鲜明但克制的色域关系。

如果工具支持交互选择，展示三个方向后暂停；如果不支持，则自行选择最符合“长期使用、安静但不平庸”的一套继续设计。

色彩系统只遵循以下抽象规则：
- 建立 Neutral 色阶 N0～N1000，用于画布、表面、文字、分隔与反转文字。
- 建立 Primary 色阶 P50～P900，用于品牌、交互、选中状态和必要的区域区分。
- 可选建立 Accent 色阶 A50～A700，但同一屏幕只允许一种非语义辅助色。
- success、warning、danger、info 使用独立语义色阶，不与项目识别色混用。
- 大面积相邻表面通常只跨越 1～2 个色阶，避免从最浅直接跳到最深。
- 最深色和最高饱和色主要用于文字、主要操作、焦点和小面积状态；浅色主题中，它们合计不宜超过首屏面积的约 10%。
- 主色至少在三个不同层级产生呼应，例如交互状态、轻量背景和数据表达，但不要机械地给所有组件染色。
- 色彩层级必须服从信息层级：重要性首先由位置、尺寸、排版和空间确定，颜色只辅助分区。
- 不使用孤立且没有呼应的强调色，不使用彩虹渐变、霓虹光效、玻璃拟态或大面积装饰渐变。
- 所有文字与交互状态满足 WCAG AA；focus-visible 可以使用高对比色，但只在键盘交互时出现。
- 深色主题从同一套色阶和语义角色映射产生，保留相同布局、间距和组件关系，不能另起一套视觉风格。

不要人为指定一个巨大的深色内容卡片作为“视觉锚点”。生产力工具的层级应来自用户注意力路径，而不是 Hero 区：用户先看到今天要继续的工作和待办，再扫到最近内容与项目进度。通过位置、尺寸、排版和中浅色阶共同建立这条路径。

内容区使用“分布式视觉节奏”：
- 在首屏安排 2～4 个面积不同但相互平衡的功能区域，通过表面色阶形成适度区分。
- 允许“继续工作”更宽、位置更靠前，但它不能同时成为面积最大、颜色最深、对比最强的孤立色块。
- 大多数内容面板使用相邻的中性或主色色阶，不让任何单一模块脱离整体色阶体系。
- 主次关系优先由栅格位置、标题层级和内容密度建立，颜色只负责分区和节奏。
- 避免侧栏和右侧或中央内容卡片形成互相拉扯的视觉极点。

请同时定义颜色 token，并保证文字与背景达到 WCAG AA 对比度。可以提供浅色主主题；若生成深色主题，深色版必须是同一设计系统的映射，而不是另一个产品。

三、组件与造型约束

- 以实心色块、背景层级、留白和排版建立层次，尽量不用边框分隔。
- 禁止“每一块内容都装进白色描边圆角卡片”的 card soup。
- 只有表格、输入焦点、危险确认和必要分隔处可以使用细线。
- 主要按钮使用实心高对比填充；具体色相由最终色彩系统决定。次要操作使用低对比填充或纯文字。
- 禁止大面积线框按钮，禁止成排 outline pill buttons。
- 圆角统一且克制：小控件 8px 左右，大面板 12～16px；不要所有元素都做成胶囊。
- 阴影非常轻，只用于浮层、编辑器工具栏和移动端抽屉；页面层级主要依靠色块而不是阴影。
- 图标使用简洁、统一笔触的开源图标风格，但图标不要取代清晰文本。
- 字体采用现代中性无衬线字体，中文可使用 Noto Sans SC 或系统黑体，拉丁字符可使用 Geist/Inter。等宽字体只用于代码、快捷键与少量技术元数据。
- 标题层级明确，但不要用巨型营销页标题占据生产力界面。
- 使用真实中文产品文案，不使用 lorem ipsum。
- 所有页面必须使用同一设计系统、同一栅格、同一间距尺度和同一交互语法。

四、全局应用框架

桌面端优先，基准画板为 1440×1024，同时展示 1280px 适配逻辑。

桌面布局：
- 左侧固定主侧栏，宽度约 220～248px。
- 侧栏与内容画布必须能通过表面层级、间距或轻量分隔清楚区分，但不要预设侧栏必须比内容区更深、更浅或使用某种具体色相。
- 当前导航使用实心低对比选中背景、清晰文字和图标，不依赖描边；选中项不能仅靠颜色表达状态。
- 侧栏不能成为全页最强视觉区域。若设计工具选择高对比侧栏，应控制其色差和面积带来的视觉重量，并证明它不会与主要内容竞争。
- 品牌和当前工作空间位于顶部。
- Dashboard、Notes、Links、Projects、Tasks、Search、Reviews 位于侧栏垂直中部，形成稳定且有呼吸感的导航组。
- Settings、主题切换和用户账户位于底部。
- 侧栏不要塞入标签树、文件树或过多次级导航。
- 内容页顶部使用简洁的上下文标题、全局搜索入口和一项主要操作，不设置拥挤的传统顶栏。
- 提供全局快速捕获入口，支持新建 Note、Link、Task；桌面端同时提示快捷键，例如 Cmd/Ctrl + K 或 N。

响应式规则：
- 1024px 以下侧栏收起为图标栏或抽屉，内容由多列降为单列或双列。
- 768px 以下进入移动布局，不是简单缩小桌面稿。
- 移动端优先保留 Dashboard、Notes、Projects、Tasks 和快速新增，可使用底部导航；其他模块进入“更多”。
- 移动端快速捕获使用底部抽屉；筛选器使用全屏或底部 Sheet。
- 编辑器移动端隐藏元数据侧栏，将属性放入顶部动作或底部 Sheet；正文保持舒适行宽和可触达工具栏。
- 表格在移动端改为结构化列表，不出现横向压缩到不可读的表格。

五、需要生成的完整 MVP 页面

请为以下页面生成高保真桌面稿，并为关键页面补充移动端稿。所有页面使用一致的应用框架。

01. 登录页
- 邮箱、密码、登录按钮、明确错误状态。
- 单用户工具的安静入口，不做营销落地页，不展示第三方登录和企业宣传。
- 使用一个有识别度的主色块建立品牌气质。

02. Dashboard
- 只展示真正支持“恢复上下文和开始工作”的内容：今日待办、最近编辑笔记、最近保存链接、活跃项目、本周进度、快速捕获。
- 不要成排四个通用统计卡，不要大型无意义折线图。
- 建议使用 12 栏栅格组织 4～6 个相互平衡的功能区。首行可采用约 7:5 的双栏工作带：“继续工作”较宽，“今日待办”较窄，两者高度接近并共同形成第一注意层级。
- “继续工作”通过更宽的位置、清晰标题和主要操作体现优先级。
- 第二层级由最近笔记、最近收藏和本周进度组成。
- 活跃项目位于下一行，以紧凑横向模块延续色彩节奏；项目识别色只占很小面积。
- 第一屏控制信息量，让用户能在 5 秒内知道今天做什么、最近在哪个项目工作、如何快速记录。

03. Notes 笔记列表
- 支持标题、摘要、标签、项目、更新时间、收藏状态。
- 支持按标签、项目、收藏、更新时间筛选，支持按最近更新、最近创建、标题排序。
- 不使用卡片瀑布流。采用易扫读的列表或主从分栏：列表保持紧凑，选中后可显示轻量预览。
- 需要包含默认、筛选中、无结果和空状态。

04. Note 编辑/详情页
- 编辑体验是产品核心。正文居中，建议正文最大宽度 760～840px，周围有足够留白。
- 桌面端结构为：可折叠应用侧栏 + 编辑器画布 + 可折叠属性面板。属性面板包含项目、标签、关联任务、收藏、附件、创建/更新时间。
- 顶部显示返回、标题、保存状态、预览切换和更多操作，避免拥挤。
- 支持 Markdown、标题层级、列表、引用、链接、表格、代码块和语法高亮。
- 文本选中时出现紧凑的实心深色浮动工具栏；不要白色描边按钮条。
- 提供编辑、分栏预览、只读预览三种状态，但默认编辑界面不要一直占用双栏。
- 设计手动保存状态、未保存状态、保存中、保存失败、删除二次确认。
- 视觉上像专注写作工作台，不像博客文章页，也不像团队在线文档。

05. Links 链接库
- 展示标题、域名、描述、标签、所属项目、阅读状态、收藏和创建时间。
- 支持未读、已读、稍后再读以及标签、项目、域名筛选。
- 使用紧凑列表或分组流，不做带大缩略图的资讯卡片墙。
- 新建链接使用低摩擦右侧抽屉或居中对话框：URL 最突出，标题和描述允许稍后补充，并设计重复 URL 提示。

06. Projects 项目列表
- 展示项目名称、目标、状态、技术栈、近期活动和下一项任务。
- 状态包括计划中、进行中、暂停、完成、归档。
- 用有重量的色块区分活跃项目，但不要做成同质化卡片网格；可采用重点项目大块 + 其他项目紧凑列表。
- 包含项目创建、状态筛选和归档入口。

07. Project 项目详情
- 顶部快速回答：项目目标是什么、当前处于什么状态、下一步做什么。
- 包含 Overview、Board、Notes & Links、Files、Reviews、Activity 等页签或分区。
- Overview 展示当前焦点、进度、近期活动、关联笔记、链接和关键任务。
- Board 为待处理、进行中、已完成三列；卡片紧凑，支持拖拽、优先级、截止日期和快速新增。
- 项目详情不要变成企业项目管理软件，不显示成员、工时、预算或团队负载。

08. Tasks 任务页
- 支持项目、状态、优先级筛选和截止日期排序。
- 默认使用结构化列表，清楚展示标题、项目、状态、优先级和截止日期。
- 支持行内完成、快速新增和侧边详情抽屉。
- 状态为待处理、进行中、已完成、已取消；优先级为低、中、高。

09. Global Search 搜索结果页
- 顶部为醒目的全局搜索输入框，结果覆盖 Notes、Links、Projects、Tasks。
- 支持类型、标签、项目和时间范围筛选。
- 每条结果突出标题、类型、命中摘要、项目、标签和更新时间。
- 设计键盘上下选择与回车打开的状态，但不要把界面做成命令行。
- 包含初始状态、搜索中、混合结果、无结果状态。

10. Tags 标签管理
- 展示标签名称、颜色、使用次数和最近使用时间。
- 支持创建、改名、改色和删除，删除标签时明确说明不会删除关联内容。
- 标签颜色来自受控色板，不允许用户生成刺眼或低对比颜色。

11. Reviews 回顾列表
- 展示周回顾和项目回顾，按时间组织。
- 用时间段、关联项目和简短摘要帮助用户重新进入上下文。
- 不使用社交动态流样式。

12. Review 回顾编辑页
- 自动聚合指定时间范围内完成的任务、新建笔记、保存链接和项目状态变化。
- 正文区包含：本期总结、遇到的问题、学到什么、下一步。
- 自动聚合区与用户书写区清晰区分，但保持在同一页面，不做复杂报表。
- 支持关联多个项目和保存状态。

13. Settings 设置页
- 个人资料：用户名、邮箱只读或提示修改流程、头像。
- 偏好：默认首页、浅色/深色/跟随系统、编辑器偏好。
- 数据与危险区：导出入口占位、退出登录、清除或删除操作的危险确认。
- 使用清晰分区，不使用传统设置卡片矩阵。

14. Global Quick Capture 全局快速捕获
- 通过快捷键或主要新增入口打开。
- 首先选择 Note、Link 或 Task，也可以根据输入内容智能预选，但不要引入复杂 AI 功能。
- 默认只要求最少字段，项目与标签可选，支持“保存并继续”和“保存后打开”。
- 设计桌面对话框和移动端底部 Sheet。

15. 系统状态与反馈
- 为关键页面提供 loading skeleton、空状态、错误状态、保存成功、保存失败、离线或网络异常提示。
- 删除 Note、Project 归档、删除 Tag 等危险操作必须有清晰确认。
- 空状态应给出明确下一步，不使用无意义插画占据大面积空间。

六、示例内容

使用真实、克制的中文开发者内容填充设计：
- 项目：MindForge、FlowPilot、Spring Security Lab、Frontend Patterns。
- 笔记：Session 与 CSRF 生命周期、Next.js 同源代理方案、PostgreSQL 全文搜索取舍、Note 软删除设计。
- 任务：打通登录到 Note CRUD、补全编辑器保存状态、实现 Tag 筛选、验证移动端导航。
- 链接：Spring Security Reference、Next.js Documentation、PostgreSQL Full Text Search。
- 标签：security、next.js、postgresql、architecture、debugging。

不要出现销售额、客户数、订阅收入、团队成员、发票或营销活动等与产品无关的数据。

七、设计系统交付要求

在页面之外，生成或明确以下内容：
- 颜色 token：background、surface、ink、muted、accent 色阶、success、warning、danger。
- 排版层级：页面标题、区块标题、正文、列表标题、辅助信息、代码与快捷键。
- 4/8pt 间距系统和桌面/移动栅格。
- 按钮：primary、secondary filled、tertiary text、danger；不要 outline 作为常规类型。
- 输入框、搜索框、Select、Tag、状态标记、Tooltip、Dropdown、Dialog、Drawer、Toast。
- 列表行、内容面板、编辑器工具栏、代码块、看板任务卡。
- 默认、hover、focus-visible、active、disabled、loading、error 状态。
- 键盘焦点必须清晰；不要为了“无边框”牺牲可访问性，focus ring 只在交互时出现。

八、明确禁止

- 不要生成千篇一律的 SaaS Admin Dashboard。
- 不要 card soup，不要每个模块都用白色描边圆角卡片。
- 不要成排 KPI 数字卡，不要为了填满 Dashboard 添加无业务意义的图表。
- 不要线框按钮作为主要设计语言。
- 不要过度使用胶囊、渐变、玻璃拟态、霓虹、发光描边和悬浮阴影。
- 不要 Notion、Linear、Obsidian 或参考产品的直接复刻。
- 不要知识星图、节点网络、纸张手账、终端命令行或像素复古主题。
```

## 分批生成顺序

## 评估候选工具输出的检查表

- 第一眼是否像个人知识工作台，而不是财务或企业管理后台？
- Dashboard 是否帮助恢复工作上下文，而不是展示一排统计数字？
- 功能区域是否通过布局、排版、空间和表面层级形成质感，而不是依赖装饰渐变？
- Dashboard 是否通过分布式区域和注意力路径建立层级，而不是依赖一块巨大的高对比视觉锚点？
- 最终配色是否拥有完整的 Neutral、Primary、Accent 与语义色阶？
- 相邻大面积表面是否沿色阶平滑过渡，最深色和高饱和色是否只占小面积？
- 侧栏是否清楚可辨但不过度支配页面，并且没有被预设为某一种具体色相？
- 是否避免任何大面积高对比模块与画布形成生硬的二元切割？
- 是否避免了大量描边卡片与线框按钮？
- Note 编辑器是否真正适合长时间写 Markdown 和代码？
- Notes、Links、Projects、Tasks 是否有明确但一致的内容结构？
- 桌面侧栏中部导航是否成立，底部账户区是否稳定？
- 移动端是否重新组织操作，而不是简单缩小桌面页面？
- 页面能否由常见开源图标、编辑器和前端组件实现？
- 不看 Logo 时，是否仍能从色彩、布局和交互语言认出这是同一个产品？
